## 3. Code Pattern Chuẩn Ngành (Boilerplate – Rủi ro rất thấp)

Đây là các pattern được dùng phổ biến trong cộng đồng, không ai sở hữu chúng.

### 3.1 `frontend/src/api.ts` – Axios interceptor

```ts
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

**Nhận xét:** Pattern Axios + Bearer token interceptor xuất hiện ở hàng trăm ngàn tutorial/blog. Đây là cách chuẩn duy nhất để làm việc này. **Không phải đạo văn.**

### 3.2 `frontend/src/authService.ts` – JWT localStorage

Pattern lưu JWT token vào `localStorage`, parse user từ JSON, `logout` bằng cách xóa `localStorage` – đây là pattern chuẩn của mọi SPA React. **Không phải đạo văn.**

### 3.3 `backend/Program.cs` – ASP.NET Core 6+ minimal hosting

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)...
var app = builder.Build();
app.UseAuthentication(); app.UseAuthorization();
app.MapControllers();
app.Run();
```

**Nhận xét:** Đây là cấu trúc khởi động chuẩn từ tài liệu Microsoft. Không thể viết theo cách khác với .NET 6+. **Không phải đạo văn.**

### 3.4 `backend/Data/AppDbContext.cs` – EF Core DbContext

Cấu hình `OnModelCreating` với relationships (HasOne/WithMany/HasForeignKey) là pattern chuẩn của EF Core. **Không phải đạo văn.**

### 3.5 `backend/Controllers` – CRUD Controller pattern

Tất cả controller đều theo cấu trúc `[ApiController]` + `[Route("api/[controller]")]` với `try/catch` + `StatusCode(500)` khi lỗi – đây là scaffolding pattern của ASP.NET Core. **Không phải đạo văn.**

## 4. Khu vực Rủi ro Trung bình (Sát Tutorial Phổ biến)

Đây là những đoạn code trùng khớp rất cao với các tutorial online nổi tiếng.

### 4.1 `backend/Controllers/AuthController.cs` – JWT Token Generation

```csharp
var tokenHandler = new JwtSecurityTokenHandler();
var key = Encoding.UTF8.GetBytes(secretKey!);
var tokenDescriptor = new SecurityTokenDescriptor {
    Subject = new ClaimsIdentity(new[] { new Claim("userId", user.Id.ToString()) }),
    Expires = DateTime.UtcNow.AddHours(24),
    SigningCredentials = new SigningCredentials(...)
};
```

**Risk:** Pattern này xuất hiện gần như nguyên xi trong tutorial chính thức của Microsoft tại `docs.microsoft.com/aspnet/core/security/authentication/jwt-authn`. Rất khó phân biệt với tutorial.  
**Khuyến nghị:** Thêm comment `// Based on Microsoft JWT authentication docs` hoặc ghi trong báo cáo.

### 4.2 `backend/Controllers/DocumentController.cs` – File Upload

```csharp
var uniqueFileName = $"{Guid.NewGuid()}_{file.FileName}";
var filePath = Path.Combine(uploadDir, uniqueFileName);
using (var stream = new FileStream(filePath, FileMode.Create)) {
    await file.CopyToAsync(stream);
}
```

**Risk:** Đoạn upload file lưu với `Guid.NewGuid()` + `CopyToAsync` là pattern xuất hiện trực tiếp trong tài liệu Microsoft "Upload files in ASP.NET Core". Khá sát tutorial.  
**Khuyến nghị:** Ghi chú nguồn trong báo cáo kỹ thuật.

### 4.3 `backend/Services/EmailService.cs` – Email với HTML body

Pattern tạo HTML email template trong C# bằng string interpolation `$@"<html>..."` là rất phổ biến và xuất hiện trong nhiều tutorial SMTP. Tuy nhiên phần này chưa implement thực sự (chỉ log), nên rủi ro thấp hơn.

### 4.4 `frontend/src/Login.tsx` & `Register.tsx` – Form với controlled components

```tsx
const [email, setEmail] = useState("");
const handleSubmit = async (e: FormEvent) => {
  e.preventDefault();
  // ...

```

**Risk:** Đây là React controlled form pattern chuẩn nhất. Tuy nhiên cấu trúc tổng thể (state per field, try/catch trong submit, navigate sau login) rất giống các tutorial "how to build a login form in React". Mức rủi ro **thấp** vì không có lựa chọn nào khác để triển khai form React.

## 5. Code Gốc / Nghiệp vụ Đặc thù (Không phải đạo văn)

Đây là phần **hoàn toàn gốc** của dự án, thể hiện công sức thực sự của nhóm.

- `Topic.CanSubmitIdea()` / `Topic.CanComment()` – kiểm tra deadline động
- Hệ thống **anonymous ideas/comments** với logic ẩn tên tác giả

- Logic ngăn user tự xóa tài khoản của mình trong `AdminController.cs`

### 5.2 `backend/Program.cs` – `NormalizeSeedContentToEnglishAsync`

Function startup-time data normalization dùng EF Core để dịch seed data – đây là giải pháp sáng tạo và **không thể tìm thấy trong bất kỳ tutorial nào**. **100% gốc.**

### 5.3 `frontend/src/AdminDashboard.tsx`

Dashboard quản trị với multi-tab (overview/users/topics/categories/statistics/topicIdeas), xuất CSV/ZIP, quản lý user CRUD – đây là code hoàn toàn custom cho nghiệp vụ của project. **Gốc.**

### 5.4 `backend/Controllers/AdminController.cs`

- ZIP export documents (`System.IO.Compression`) per topic
- CSV export ideas per topic
- Soft delete user (set `IsActive = false`)

### 5.5 `backend/Controllers/StatisticsController.cs`

Các endpoint thống kê (ideas-by-category, ideas-by-topic, top-contributors, ideas-timeline với date filter) được thiết kế riêng cho yêu cầu báo cáo của hệ thống. **Gốc.**

### 5.6 `frontend/src/services/` – Service layer

Toàn bộ service layer (10 files) wrapping API calls với typed return types – thiết kế tách biệt service layer là quyết định kiến trúc của nhóm. **Gốc.**

### 5.7 Schema dữ liệu

`backend/Models/` (User, Idea, Topic, Category, Department, Comment, Reaction, Document, SystemSettings) với các quan hệ đặc thù (Department → QACoordinator, Idea → anonymous) – thiết kế riêng. **Gốc.**

Codebase **không có bất kỳ copyright header nào** trong các file source. Đây vừa là điểm tích cực (không sign-off từ nguồn khác) vừa là điểm cần cải thiện nếu nộp bài.

Các đoạn code sát tutorial (JWT, file upload) không có comment ghi rõ "based on / adapted from". Nếu giám khảo tra Google thì có thể bị nghi ngờ.

`Login.tsx` hard-code test accounts trong UI:


Đây không phải đạo văn nhưng là **security issue** khi nộp bài hoặc deploy.

#### `api.ts` — Pattern chuẩn, nhưng có customization thông minh

```ts
// Axios interceptor request – standard boilerplate
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// Response interceptor – CUSTOM: tự redirect về /login khi 401
apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem("token");
      window.location.href = "/login";
    }
    return Promise.reject(error);
  },
);
```

- Request interceptor: boilerplate chuẩn, tìm ngàn chỗ.
- Response interceptor với auto-redirect: cũng phổ biến nhưng logic cụ thể (xóa token + redirect) là quyết định của nhóm.

#### `NavBar.tsx` — Đây là phần SÁNG TẠO nhất frontend

```ts
// Animated sliding indicator dùng requestAnimationFrame
useEffect(() => {
  const update = () => {
    const activeEl = nav.querySelector<HTMLElement>(".tab-btn.tab-active");
    if (activeEl) {
      setIndicator({
        left: activeEl.offsetLeft,
        width: activeEl.offsetWidth,
        ready: true,

  const raf1 = requestAnimationFrame(() => {
    const raf2 = requestAnimationFrame(update);
    return () => cancelAnimationFrame(raf2);
```

**Double-nested requestAnimationFrame** để đảm bảo DOM render xong trước khi tính vị trí indicator — đây là kỹ thuật nâng cao, không xuất hiện trong tutorial React Navbar thông thường. Logic tab generation với `show` condition theo role cũng gốc. **Kết luận: Rất thấp / Gốc hoàn toàn.**

#### `AuthController.cs` — ✅ ĐÃ VIẾT LẠI – Rủi ro THẤP

`GenerateJwtToken()` đã được tái cấu trúc thành 3 phương thức riêng biệt với cấu trúc hoàn toàn khác tutorial:

```csharp
// 1. Main method dùng SecurityTokenDescriptor (không phải JwtSecurityToken constructor)
private string GenerateJwtToken(User user)
{
    var (signingKey, issuer, audience, expiryMinutes) = LoadJwtConfig();
    var descriptor = new SecurityTokenDescriptor
    {
        Subject = new ClaimsIdentity(BuildClaimsForUser(user)),
        NotBefore = DateTime.UtcNow, IssuedAt = DateTime.UtcNow,
        Expires = DateTime.UtcNow.AddMinutes(expiryMinutes), ...
    };
    var handler = new JwtSecurityTokenHandler();
    return handler.WriteToken(handler.CreateToken(descriptor)); // 2-step
}

// 2. Config loader trả về tuple
private (SymmetricSecurityKey Key, ...) LoadJwtConfig() { ... }

// 3. Claims builder dùng yield iterator
private static IEnumerable<Claim> BuildClaimsForUser(User user)
{
    yield return new Claim("userId", user.Id.ToString());
    yield return new Claim("jti",    Guid.NewGuid().ToString("N")); // unique token ID
    yield return new Claim("termsAgreed", user.AgreedTerms ? "1" : "0"); // domain-specific
    // ...
}
```

Khác biệt cốt lõi so với tutorial: `SecurityTokenDescriptor` thay `JwtSecurityToken` constructor, `handler.CreateToken(descriptor)` 2-step, `yield return` iterator, claims domain-specific (`jti`, `termsAgreed`, `studentId`), tuple return type. **Mức độ trùng mới: ~25%.**
